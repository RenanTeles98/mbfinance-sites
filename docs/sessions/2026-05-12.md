# Sessao 2026-05-12

## Resumo

- Removidos os carregamentos diretos de Meta Pixel, Google Analytics 4 e Google Ads do codigo fonte publico.
- Mantido o Google Tag Manager `GTM-MDST4NTK` como unico container de marketing carregado diretamente no site.
- Removidos os componentes React e arquivos JS externos que carregavam tags diretamente.
- O banner LGPD continua registrando aceite/recusa em `localStorage` e agora envia `cookie_consent_update` para o `dataLayer`, para uso em regras do GTM.

## Problemas encontrados e solucoes

- Problema: os codigos estavam espalhados em HTMLs estaticos, componentes Next.js e loaders JS centrais.
- Solucao: remover os snippets diretos e manter apenas eventos via `dataLayer`, deixando a publicacao das tags para o container do Google Tag Manager.
- Problema: o projeto separado `blog-pages/` tambem tinha componentes de Meta Pixel e Google Ads.
- Solucao: aplicar a mesma limpeza no blog para manter o padrao unico.

## Decisoes tomadas

- Google Tag Manager passa a ser a camada unica de instalacao e manutencao de tags de marketing.
- GA4, Google Ads e Meta Pixel devem ser configurados dentro do container `GTM-MDST4NTK`, nao no codigo fonte.
- A CSP continua permitindo os dominios de Google/Meta, porque as tags disparadas pelo GTM ainda precisam desses dominios no navegador.
